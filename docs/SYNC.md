# Синхронизация «Мимоходом» (протокол v1)

Телефон (Android) и компьютеры (Windows, macOS) обмениваются заметками и папками напрямую по локальной сети. Сервера в интернете нет. Протокол одинаков для всех клиентов; на Android это `SyncPlan`/`SyncClient` (Java), на компьютере — `desktop/core/src/sync` (Rust).

## Что синхронизируется

Этап 1: заметки, папки, картинки заметок. Этап 2 добавит чаты, стопки, память помощника. Не синхронизируется: ключ Polza.AI, настройки, кэш ответов, предложения напоминаний (`suggestion*`), очередь фоновой ИИ-проверки (кроме признака «проверено» и самих метаданных).

## Устройства и роли

- У каждой установки есть `device` — случайный UUID (32 hex без дефисов) и имя для людей.
- Компьютер умеет быть **сервером** (слушает TCP-порт) и **клиентом**. Телефон — только клиент: запускает обмен сам (кнопка, открытие приложения, периодически на переднем плане).
- Два компьютера: оба сервера; тот, кто вводил код сопряжения, — клиент при первом обмене, адрес первого передаётся в запросе (`hosts`), и дальше любой может начать обмен.

## Сопряжение

1. Компьютер создаёт одноразовый `secret` (16 случайных байт) на 10 минут и показывает строку и QR-код:
   `mimohodom://pair?v=1&id=<device>&n=<имя, urlencoded>&s=<secret, base64url без =>&h=<ip:port,ip:port>`
2. Второе устройство вводит строку (вставка или QR) и сохраняет у себя узел: `device`, имя, `secret`, `hosts`.
3. Первый же запрос от нового устройства расшифровывается ожидающим `secret`; если получилось, сервер сохраняет узел навсегда (тот же `secret`), одноразовый код гаснет. Три неудачные попытки гасят код раньше.
4. Удаление узла на любой стороне разрывает связь; для новой нужен новый код.

Ключ шифрования: `key = HKDF-SHA256(secret, salt = "", info = "mimohodom-sync-v1")`, 32 байта.

## Транспорт

HTTP/1.1 по TCP, порт по умолчанию 47616 (если занят — свободный, он указывается в `h`). Все тела шифруются AES-256-GCM: `nonce(12 байт) || шифртекст || тег(16)`. Свой `nonce` на каждое сообщение. Заголовок `X-Mimo-Device: <device отправителя>` открыт. Дополнительные аутентифицируемые данные (AAD): запрос — `"req|" + device отправителя`, ответ — `"res|" + device отправителя запроса`.

Открытый путь `GET /v1/ping` отвечает `mimohodom` и ничего более.

Внутри запроса JSON с полями `v` (1), `ts` (мс, допуск ±10 минут), `rid` (случайная строка; сервер помнит 15 минут и отклоняет повтор).

Обнаружение адреса: UDP-широковещание на порт 47615. Клиент шлёт `MIMO?<device сервера>`, сервер с таким `device` отвечает отправителю `MIMO!<device>:<порт>`. Секретов в этом обмене нет.

## Эндпоинты

`POST /v1/sync` — обмен записями. Запрос:

```json
{"v":1,"ts":0,"rid":"…","device":"…","name":"Pixel","hosts":["192.168.1.5:47616"],
 "since":0,"limit":300,"first":true,"records":[…]}
```

- `records` — записи клиента, изменённые после предыдущей отправки (по возрастанию `seq`).
- `since` — порядковый номер на стороне **сервера**, после которого клиент ещё не получал изменений.
- `first` — первая страница обмена: сервер обязан приложить **все** папки (и надгробия папок) независимо от `since`, чтобы ссылки заметок на папки всегда разрешались.

Ответ:

```json
{"v":1,"records":[…],"next":123,"more":false,"want":["<файл>.jpg"],"name":"ПК","device":"…"}
```

- `next` — новое значение `since` для клиента (если `more` — номер последней отданной записи, иначе текущий `seq` сервера).
- `want` — файлы картинок, на которые сервер уже ссылается, но у него их нет.

Обмен — цикл: страницы отправки клиента по 200 записей и страницы ответа, пока `more` не станет ложью и клиент не отправит всё. Затем:

`POST /v1/blob/get` — тело `{"name":"…"}`, ответ — зашифрованные байты файла; `404` без тела, если файла нет.
`POST /v1/blob/put` — тело `{"name":"…","data":"<base64>"}`, ответ `{"ok":true}`.

Имя файла: `^[A-Za-z0-9._-]{1,80}$`, без `..`. Клиент после обмена: скачивает все файлы, на которые ссылаются его заметки, но которых нет локально; загружает файлы из `want`, которые есть у него.

## Модель записей

Общие поля: `kind` (`note`/`folder`), `uid`, `ts`, `deleted`. Удалённая запись содержит только эти четыре поля (надгробие).

`note`: `title`, `body`, `created`, `updated`, `reminder`, `repeat`, `lead`, `images` (массив имён файлов), `folder` (`uid` папки или пустая строка), `titleAuto` (bool), `aiChecked` (bool), `metadata` (строка JSON).

`folder`: `name`, `key`, `created`, `auto` (bool).

`uid` заметки — случайный UUID без дефисов. `uid` папки — первые 32 hex от `SHA-256("folder:" + key)` на момент создания, поэтому одноимённые папки с разных устройств сливаются сами; переименование `uid` не меняет.

Не передаётся и пересчитывается на месте: `search_text` (из `metadata`), индекс поиска, номера (`id`) строк.

## Порядок и разрешение конфликтов

На каждом устройстве у каждой записи три служебных поля (не входят в запись, кроме `ts`):

- `sync_ts` (`ts`) — гибридные логические часы: `max(часы устройства, последний увиденный ts + 1)`. Определяет победителя: **побеждает запись с большим `ts`**; удаление — тоже запись. При равенстве остаётся локальная.
- `sync_seq` — локальный монотонный счётчик изменений устройства. По нему отбираются записи для отправки (`seq` больше, чем при прошлой отправке этому узлу) и для ответа (`seq` больше `since`).
- `sync_from` — `device` узла, от которого запись принята; такую запись узлу обратно не возвращают.

Узел хранит для каждого соседа `sent_seq` (до какого локального `seq` отправлено) и `got_seq` (последний `next`).

Конфликт правки: если побеждает чужая запись заметки, но локальная заметка тоже менялась после прошлой отправки этому узлу (`seq > sent_seq`) и её название или текст отличаются, локальная версия сохраняется отдельной заметкой с названием «… (копия при конфликте)». Данные не теряются.

Правка заметки после её удаления на другом устройстве воскрешает заметку, если правка новее надгробия; иначе удаление побеждает.

Удаление папки возвращает её заметки в «Все заметки» (`folder = ""`), эти заметки получают новый `ts`.

## Безопасность

- Всё содержимое шифруется и аутентифицируется общим ключом; без `secret` сервер ничего не отдаёт.
- Сервер слушает только пока включена синхронизация; порт открыт в локальной сети.
- Утечка кода сопряжения (например, снимок экрана QR) даёт доступ ко всем заметкам, пока узел не удалён. Код живёт 10 минут и действует один раз.
- Подмена времени ограничена окном ±10 минут; повтор перехваченного запроса отклоняется по `rid`.
