# Проверка приложения агентом через консоль

Все действия пользователя доступны как консольные команды, поэтому ИИ-агент может проверять «Мимоходом» сам: нажимать кнопки, вводить текст, листать вкладки, читать экран и базу, смотреть логи и падения.

Работает так: сборка `agent` (то же приложение + мост `AgentProvider`) принимает команды от `adb shell`, а `scripts/agent.mjs` прячет всю возню с adb за одной строкой.

```
агент → node scripts/agent.mjs ui.tap "Сохранить заметку" → adb → AgentProvider → экран приложения
```

## Подготовка

1. Нужны Node.js и adb (клиент сам берёт `.tools/android/platform-tools/adb`, иначе `adb` из PATH или переменная `ADB`).
2. Собрать и поставить сборку agent. Она имеет тот же `applicationId` (`app.fastnotes`) и ключ подписи, что `debug`, поэтому ставится поверх, данные сохраняются:

```bash
node scripts/agent.mjs build
node scripts/agent.mjs install
node scripts/agent.mjs doctor
```

3. Запустить: `node scripts/agent.mjs launch`. Экран устройства должен быть разблокирован.

**Безопасность.** Мост есть только в сборке `agent` (`assembleAgent`); в `debug` из CI и в `release` его нет. Провайдер требует разрешение `android.permission.DUMP` (его имеет оболочка adb, обычные приложения — нет) и проверяет uid вызывающего. Ключи и токены из настроек в ответах скрыты, поля с ключами в `ui.dump` показываются как `•••`. Всё равно ставьте сборку agent на тестовое устройство или эмулятор: команды могут создавать и менять заметки.

## Формат команд

```
node scripts/agent.mjs <команда> [аргументы] [--опция=значение] [--флаг]
```

- Аргументы с пробелами берите в кавычки как обычно в вашей оболочке: клиент сам передаёт их в мост без искажений.
- Значение опции — только через `=`: `--nth=1`. Флаг — просто `--exact`.
- Ответ — текст для чтения. `--json` выдаёт сырой JSON `{ok, text, data, error, hint, ms}`. При ошибке код выхода 1, в `ОШИБКА:` причина, в `подсказка:` — что сделать.
- `node scripts/agent.mjs help` — актуальный список всех команд.

### Цели для нажатия и ввода

| Запись | Что находит |
| --- | --- |
| `@12` | элемент №12 из последнего `ui.dump` |
| `desc:Назад` | по описанию для доступности (`contentDescription`) |
| `text:Сохранить` | по видимому тексту |
| `hint:Сообщение` | по подсказке пустого поля |
| `class:EditText` | по классу |
| `Сохранить заметку` | без префикса: текст, описание или подсказка |

Точное совпадение без учёта регистра важнее вхождения. Если совпадений несколько, берётся первое сверху и в ответе перечислены остальные; уточняйте `--nth=N`, `--exact` или `@N`. Окно диалога перекрывает остальные: элемент под диалогом нажать нельзя, как и пользователю.

## Что делает пользователь → команда

| Пользователь | Команда |
| --- | --- |
| Видит экран | `ui.read` (тексты) или `ui.dump` (элементы, границы, признаки) |
| Нажимает кнопку | `ui.tap "Сохранить заметку"` |
| Долго нажимает | `ui.longpress "…"` |
| Касается точки | `ui.tapxy 540 1200` |
| Печатает | `ui.type "текст"` (в сфокусированное поле) или `ui.type "текст" --target=hint:Название` |
| Очищает поле | `ui.clear hint:Название` или `ui.type "новый" --replace` |
| Нажимает «Назад» | `ui.back` (закрывает диалог, меню, страницу) |
| Клавиша Enter | `ui.key enter` |
| Листает вкладки | `ui.swipe left` / `ui.swipe right` |
| Прокручивает список | `ui.scroll down` / `ui.scroll up` (`--target=` для вложенных списков) |
| Ждёт появления | `ui.wait "Заметка сохранена" --timeout=5000`, `ui.wait "Загрузка" --gone` |
| Ждёт ответа ИИ | `wait.idle --timeout=60000` |
| Открывает вкладки | `ui.tap "Заметки"`, `ui.tap "Записать"`, `ui.tap "ИИ-чат"`, `ui.tap "Настройки"` |
| Быстрые действия значка | `shortcut new-note\|new-chat\|notes\|search` |
| Открывает заметку из уведомления | `open-note 42` |
| «Поделиться» текстом или ссылкой | `share-text "https://…"` |
| Пишет в чат | `chat.send "вопрос"`, затем `wait.idle` и `chat.messages` |
| Видит снимок экрана | `shot` (путь к PNG печатается) |

После каждого действия ответ содержит состояние `page=… tab=…` до и после: так видно, сработало ли нажатие. Паузу после действия можно менять `--settle=мс` (по умолчанию 400 для нажатий: анимации вкладок идут 280 мс). `--click` вызывает обработчик напрямую вместо настоящего касания (запасной вариант, если касание что-то перехватывает).

Идентификаторы страниц (`page`): `home` — «Записать», `edit` — заметка, `notes`, `manager`, `chats`, `chat`, `settings`, `settings.ai|reminders|assistant|app`. Вкладки (`tab`): 0 — «Заметки», 1 — «Записать», 2 — «ИИ-чат», 3 — настройки.

## Данные и состояние (без интерфейса)

| Команда | Назначение |
| --- | --- |
| `state` | страница, вкладка, открытая заметка/чат, окна, фоновые задачи |
| `notes.list`, `notes.get <id>`, `notes.search "запрос"` | заметки как в приложении |
| `notes.create "название" "текст"` | подготовить заметку; затем `app.render` |
| `notes.seed --count=30`, `notes.unseed` | тестовые заметки с меткой `[agent]` и удаление только их |
| `reminders.list`, `folders.list`, `chats.list`, `chat.messages [id]` | остальные таблицы |
| `prefs.get [часть имени]`, `prefs.set имя значение --type=bool` | настройки (после `prefs.set` — `app.recreate`) |
| `db.query "SELECT …"` | SQL только на чтение (отдельное соединение `OPEN_READONLY`) |
| `crash.last`, `crash.clear` | стек последнего падения процесса |
| `history` | последние команды моста и итог |
| `logcat [--bridge]` | лог приложения; `--bridge` — только команды моста |
| `native-dump` | дерево экрана через uiautomator: видит и системные окна (разрешения, выбор файла) |
| `reset --yes` | стереть все данные приложения (`pm clear`) — только тестовое устройство |

Чего изнутри приложения не сделать, решает adb: системные окна (выбор файла, камера, запрос разрешений) невидимы для `ui.dump`; используйте `native-dump`, `adb shell input tap X Y` и `shot`.

## Пример сценария: создать заметку и найти её

```bash
node scripts/agent.mjs launch --fresh
node scripts/agent.mjs ui.tap "Записать"
node scripts/agent.mjs ui.type "Купить хлеб и молоко" --target=hint:"Что хочется запомнить?"
node scripts/agent.mjs ui.tap "Сохранить заметку"
node scripts/agent.mjs ui.tap "Заметки"
node scripts/agent.mjs ui.read                     # в списке должна быть «Купить хлеб и молоко»
node scripts/agent.mjs notes.search "хлеб"          # и в базе тоже
node scripts/agent.mjs crash.last                   # падений не было
```

Тот же сценарий построчно из файла (`#` — комментарий; на первой ошибке остановка, `--keep-going` продолжает):

```bash
node scripts/agent.mjs batch scenarios/new-note.txt
```

## Как агенту отлаживать

1. `doctor` — всё ли готово. `launch` — запуск; `ui.read` — что на экране.
2. Перед нажатием смотрите `ui.dump`: нужные элементы и их `@N`. Если элемента нет — `ui.scroll down`, диалог мог его перекрыть — `ui.back`.
3. После действия сверяйте результат тремя способами: `ui.read` (что увидел пользователь), `state` (где приложение) и `notes.*`/`db.query` (что записано).
4. При странности: `crash.last`, `logcat`, `shot`. Ответ `главный поток не отвечает 15 с` значит зависание интерфейса.
5. Для платных ответов ИИ задайте ключ вручную в приложении; через мост ключ не читается и не меняется. Один `chat.send` — один платный запрос.

## Что не проверено

Мост собран и покрыт тестами разбора команд (`scripts/test-agent.ps1`); на реальном устройстве или эмуляторе его работа не проверялась. В первую очередь стоит проверить: что `content call` доходит до провайдера с DUMP, как отображаются диалоги и меню в `ui.dump` (используется скрытый список окон `WindowManagerGlobal`; если он недоступен, в ответе будет пометка, а запасной путь — `native-dump`), что настоящее касание (`MotionEvent` через окно) нажимает карточки и значки панели, и что `ui.back` действительно закрывает диалоги.
