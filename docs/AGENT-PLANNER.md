# Агент заметок — проект (черновик для обсуждения)

Ветка `agent-planner`. Не путать с `docs/AGENT.md` — там консольный мост для тестировщика.
Статус: проект и план работ (раздел 4); сделаны этапы 1, 2, 3, 4 и 7, этап 6 частично (таблица в начале раздела 4). Решения пользователя от 20.11 — в разделе 0, они главнее пометок «❓» ниже.

## 0. Решения пользователя (20.11.2026)

1. **Сам, без кнопки,** агент только даёт названия заметкам без названия. Всё остальное — через подтверждение.
2. **Удалять** агент может пустые заметки, точные дубли и заметки, целиком вошедшие в сводку, — по кнопке и только в корзину.
3. Исходные заметки группы **прячутся в колоду**, в корзину не идут.
4. **Чатов с вопросами**, которые агент начинает сам, — не больше 4 в день (экономия бюджета). **Вопросов по заметке** (в карточке и в чате по заметке) — сколько угодно.
5. Виды пунктов плана — пользователь вопрос не понял; пояснение дано в чате. Пока принято предложение: фиксированные виды (шаг, когда, кто, взять, где, заметка), текст в каждом свободный.
6. Время из плана становится напоминанием **только по нажатию**.
7. Корзина: каждая заметка удаляется насовсем через **30 дней после того, как попала в корзину** (не очистка всей корзины раз в 30 дней).
8. **Компьютер — после телефона**, телефон в приоритете.

## 1. Что есть сейчас (по коду 0.10.5)

| Что | Где | Как работает сейчас |
|---|---|---|
| Проверка заметок | `ManagerJob`, `ReviewAnalysis`, `ManagerAnalysis` | Фоном берёт пачку (`TopicSelection`), модель возвращает предложения `merge / link / task / question / clarify` и названия для заметок с `title_auto`. Названия ставятся сами, остальное — карточки в колокольчике. |
| Группы (стопки) | `ManagerStore.accept`, таблицы `note_groups`, `note_members` | `merge` и `link` создают **новую** верхнюю заметку и прячут исходники под неё. `task` и `question` создают новую заметку **без** группы — исходники остаются на виду. | Уточнения | тип `clarify`, `ManagerStore.answerClarify/answers` | Один вопрос с 2–4 вариантами про одну запись; ответ попадает в следующие проверки. |
| Вопросы о планах | `CheckIn`, `CheckInJob` | По расписанию модель пишет вопрос, создаётся **отдельный чат**; что он «от помощника», помнит только настройка `checkInChat.<id>` (не синхронизируется). |
| Несколько дат | `ReminderBatch`, `Store.acceptReminders` | Блок `[[reminders]]` → **по заметке на каждую дату**. |
| Напоминание у заметки | столбцы `reminder`, `repeat_mode`, `lead_minutes`, `suggestion*` | Одно время на заметку (+ повтор). |
| Удаление | `Store.delete` | Сразу и навсегда, корзины нет. |

Принцип, который сохраняем: **модель ничего не выполняет сама** (`ManagerAnalysis`: «No model output executes an action»). Она предлагает действия, приложение их проверяет и применяет по правилам ниже.

## 2. Как устроен агент

Один агент вместо разрозненных «менеджера», «проверки» и «вопросов о планах». У него один словарь действий; любой ответ модели — это список действий в JSON, который разбирает чистая Java (`AgentAction`, `AgentPlan` — с JVM-тестами, как `ReminderPolicy`).

### 2.1. Словарь действий

| Действие | Поля | Как применяется |
|---|---|---|
| `name` | `note`, `title` | **Само**, только если у заметки нет авторского названия (`title_auto`). С отменой. |
| `create` | `title`, `body`, `folder?` | Кнопкой «Создать». |
| `group` | `sources[≥2]`, `title`, `body` | Кнопкой. Новая заметка-сводка сверху, исходники **прячутся в колоду** под ней (не удаляются). Заменяет `merge` и `link`. |
| `trash` | `notes[]`, `reason` | Кнопкой. Только в корзину, никогда насовсем. Причины: пустая, точный дубль, полностью вошла в сводку. |
| `remind` | `note`, `times[1..N]`, `lead?`, `repeat?` | Кнопкой. **Одна заметка — несколько дат** (см. 2.3). |
| `ask` | `note`, `question`, `options[0..4]`, `kind` | Показывается как вопрос (колокольчик / карточка / чат по заметке). |
| `plan` | `note`, `tree` | Кнопкой «Сохранить план» (см. 2.5). |
| `check_in` | `note?`, `question` | Агент интересуется делами (бывший `CheckIn`), см. 2.4. |

Что агент делает сам — ❓ (предложение: только `name`; всё остальное через подтверждение). Каждое применённое действие пишется в **журнал агента** (`agent_log`: время, действие, что было до) — из него работает «Отменить» и видно, что агент сделал.

### 2.2. Группировка (то, что сейчас не так)

- Одно действие `group` вместо `merge`/`link`/`task`-с-несколькими-исходниками.
- Итог: сверху новая заметка-сводка (название + выжимка), исходники скрыты в колоде, раскрываются нажатием, «Разгруппировать» возвращает их в список.
- Если исходник целиком вошёл в сводку и пустой/дубль — агент может дополнительно предложить `trash` (отдельной галочкой в той же карточке, по умолчанию выключено) ❓.
- Новые записи по той же теме агент предлагает **добавить в существующую колоду** (обновить сводку), а не делать вторую.
- Вид: колода с наклоном (2–3 карточки под верхней, повёрнуты на ±2–4°, сдвиг 4–6 dp; при раскрытии веером). Это интерфейс, делаем после логики.

### 2.3. Напоминания: одна заметка — много дат

Сейчас `ReminderBatch` плодит заметки. Предложение — **серия по списку дат** поверх уже работающей машины повторов:

- новый `repeat_mode = LIST` и столбец `notes.reminder_times` (JSON: список моментов + `lead`);
- в `reminder` всегда лежит ближайшая дата; когда она наступает, `ReminderPolicy.advanceDue` берёт следующую из списка (как сейчас двигает ежедневную серию);
- будильник один на заметку, отложенные/пропущенные — как сейчас;
- в редакторе: «Напоминания: 3 даты» → список с удалением строк;
- отдельные заметки на каждую дату — только если у дат **разный смысл** (разные дела), это решает модель полем `separate: true`, и пользователь видит это до создания.

Синхронизация: новое поле заметки, компьютеру нужно то же правило в `core/src/reminders.rs`.

### 2.4. Вопросы: простые и сложные задачи

Агент сначала оценивает заметку (одно поле в ответе проверки, без отдельного запроса):

| Класс | Пример | Что делает агент |
|---|---|---|
| `info` | «код домофона 1234», контакт | Ничего не спрашивает. |
| `simple` | «купить хлеб», «позвонить маме» | Максимум один вопрос — «когда?» и только если напоминание уместно. |
| `event` | «врач 5 мая», «день рождения Пети» | Уточняет недостающее: время, место, что взять. |
| `complex` | «организовать выезд команды», «ремонт кухни», «переезд» | Предлагает «Разобрать план» → интервью в чате по заметке → дерево планов. |

Вопросы **не из готового списка**: в подсказке модели — перечень «пробелов», которые стоит проверить (когда / сколько дней, с кем, что взять, что подготовить, где, бюджет, срок, шаги, кто отвечает), а сам вопрос она формулирует по заметке. Правила:

- один открытый вопрос на заметку; следующий — после ответа;
- варианты ответа кнопками + свой ответ;
- ответы хранятся по заметке и всегда идут в следующие запросы (сейчас так у `clarify`) — не переспрашивать;
- лимит вопросов в день ❓ (предложение: 3), молчание растягивает интервал, как в `CheckIn` (`MAX_MISSED`);
- «интересоваться задачами»: раз в N дней агент выбирает 1–2 заметки-дела с близкими сроками или давно без движения и спрашивает «Как продвигается?» с вариантами «Сделано / В процессе / Отложить / Не актуально» — ответ меняет состояние (сделано → предложить в корзину или отметить в плане).

### 2.5. Дерево планов

Для одной задачи/события. Узлы:

| Тип | Пример | Особенность |
|---|---|---|
| `step` | «Забронировать базу» | галочка «сделано», может иметь вложенные шаги |
| `time` | «12 июня 10:00 — выезд» | одним касанием превращается в дату напоминания этой же заметки (2.3) |
| `person` | «Аня — транспорт» | кто + за что отвечает |
| `item` | «взять: палатки, аптечку» | список «взять/подготовить» с галочками |
| `place` | «база „Сосны“» | |
| `note` | свободный текст | |

Типы фиксированные, текст свободный ❓.

Хранение — предложение: столбец `notes.plan` (JSON-дерево, ≤ ~200 узлов), меняется целиком вместе с заметкой. Плюсы: одна миграция, синхронизация как поле заметки, без новой сущности в протоколе. Минус: одновременная правка плана на телефоне и компьютере — побеждает последний (как с текстом заметки сейчас).

Как строится: «Разобрать план» в заметке → открывается чат по заметке → агент задаёт 3–6 вопросов по одному (что зависит от задачи) → показывает черновик дерева → «Сохранить план». Дальше в том же чате: «добавь Олега на закупку», «сдвинь выезд на 13-е» → агент присылает действие `plan` с изменениями → кнопка «Применить».

Показ: в редакторе под текстом блок «План» (сворачиваемый), шаги с галочками, прогресс «4 из 9» на карточке заметки.

### 2.6. Чат по заметке и цвет чатов

- `chats.note` (uid заметки) и `chats.origin` (`user` / `agent` / `note`), вместо настройки `checkInChat.<id>` — тогда и цвет, и привязка синхронизируются.
- Кнопка «Обсудить» в редакторе заметки → чат с этой заметкой (один на заметку, повторное нажатие открывает тот же).
- Каждый запрос получает **свежий** текст заметки, план и ответы на уточнения (а не копию на момент создания чата).
- Изменения заметки из чата — только действиями с кнопкой «Применить» (дописать, переименовать, напоминание, план).
- Цвет в списке чатов: чаты агента — фиолетовая полоса/заливка `#F0E8FA` и пометка «От помощника» (фиолетовый в дизайн-коде уже значит «итоги помощника»); чаты по заметке — значок заметки и её название; пользовательские — как сейчас.

### 2.7. Корзина

- Столбец `notes.trashed` (время удаления, 0 — не в корзине). Все списки, поиск, напоминания, проверка агентом, ИИ-чат и выдача источников корзину не видят.
- Удаление пользователем и агентом → в корзину; «Восстановить», «Удалить навсегда», «Очистить корзину».
- Автоочистка через 30 дней ❓.
- Верхняя заметка колоды в корзину → спросить: «Удалить колоду целиком» или «Разгруппировать».
- Синхронизация: `trashed` — поле заметки; удаление навсегда — как сейчас, через `tombstones`.
- Вход: чип «Корзина» в конце ряда папок или пункт в настройках ❓.

### Этап 4. Одна заметка — несколько дат — ✅ сделан (0.10.10)

В редакторе — «Добавить ещё дату», окно «Даты напоминания» с галочками, «+N» на кнопке и карточке; время из плана — «Добавить к датам» или «Заменить». Компьютер повтор 5 не знает (этап 9).
