## Рабочий цикл пользователя
Я делаю этап → сборка → тесты → локальный коммит → отправляю APK (`dist/mimohodom-<версия>-debug.apk`, SendUserFile) → пользователь тестирует на телефоне и просит следующий шаг. Каждый релиз обновляет `AGENTS.md` (версия и поведение), `README.md`, `VERIFICATION.md`. Для установки поверх: `versionCode` растёт, `applicationId` и отладочный ключ те же. Перед выдачей APK проверить версию и подпись.
- **Нумерация версий компьютера (просьба пользователя 18.11):** `<версия Android>.<N>`, например 0.10.2.3, где 3 — номер выпуска для компьютера. 0.11.0 ≈ .1, 0.12.0 ≈ .2. В `Cargo.toml`/`tauri.conf.json`/`package.json` пишется `0.10.2-3` (semver не принимает четыре числа), в интерфейсе и документах — `0.10.2.3`. Следующий выпуск компьютера при том же Android — 0.10.2.4. Если Android уйдёт вперёд, меняются первые три числа, N продолжает счёт (допущение; первый такой случай — Android 0.10.3 → компьютер 0.10.3.5, пользователю об этом сказано, подтверждения нет).
- **Установка на телефон:** новую версию приложения всегда загружаю на телефон пользователя (`.tools/android/platform-tools/adb.exe install -r dist/mimohodom-<версия>-debug.apk`, телефон подключён по беспроводной отладке; после установки проверить `dumpsys package app.fastnotes | grep versionName`), но только после подтверждения от пользователя в чате. Без его «да» не ставлю, даже если сборка и тесты прошли. Не удалять приложение ради установки (`uninstall` сотрёт данные); при `INSTALL_FAILED_VERSION_DOWNGRADE` остановиться и сообщить.
- **CLAUDE.md нужно всегда дополнять:** после каждого этапа или изменения, которое меняет состояние проекта, договорённости с пользователем, команды сборки/запуска или правила работы, обновляй этот файл в том же сеансе (раздел «Состояние», архитектуру, «Не проверено нигде»). Устаревшее исправляй или удаляй, а не копи рядом. Новые просьбы пользователя о том, как со мной работать, записывай сюда сразу.

Агенты грузятся при старте сеанса; если тип `app-tester` не найден, запусти `general-purpose` с указанием прочитать этот файл. Без сборки `agent` на телефоне он работает в режиме «без устройства» (тесты + разбор кода).
- Телефон пользователя: Samsung SM-S938B, Android 17; на 16.11 там обычная 0.9.1 без моста — для проверки агентом нужны `node scripts/agent.mjs build` и `install`.
- Из `reports/app-test-2026-11-16-1140.md` исправлены все B1–B8 и замечания по мосту M1–M3 (0.9.3), на устройстве не проверено. Остаются «Улучшения» из раздела 3 отчёта (экспорт без картинок и чатов, текст ошибки пустого имени папки, пустая существующая заметка, резерв бюджета при остановке проверки).

## Не проверено нигде
Обмен чатами и стопками настоящего телефона с компьютером и миграция SQLite 9 → 10 на телефоне (0.10.3); `SqliteSyncStore` целиком на устройстве (JVM-тесты используют память, SQL проверен отдельно); смешанные версии устройств. Картинки 0.9.4 на телефоне: меню «Галерея/Файлы/Снимок» и системный выбор фото с несколькими снимками на Android 17, лента вложений и миниатюры в пузыре, существование и цена `google/gemini-2.5-flash` в Polza.AI, приём нескольких `image_url` и запроса до ~8 МБ, качество ответов по картинкам, повтор запроса с картинками после ошибки, освобождение файлов при удалении чата, вид ленты в редакторе заметки; UI на устройстве; запуск androidTest; Gemini Nano и GGUF на телефоне; реальные вызовы Polza.AI с картинками/видео; миграции 0.6.x → 0.9.1 на телефоне; облачная сборка Actions после 6d4f7a0.
