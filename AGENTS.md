# Мимоходом

Нативное Android-приложение на Java с локальным хранением. Текущая версия — **0.10.17** (`versionCode = 60`: устойчивый разбор ответа проверки; до неё 0.10.16, `versionCode = 59`: колода с наклоном и раскрытие веером, этап 8; до неё 0.10.15, `versionCode = 58`: длина ответа «Обычно» 2000 и «Подробно» 3000 токенов, по ней же потолок проверки; до неё 0.10.14, `versionCode = 57`: компактный ответ общей проверки — платный прогон показал обрыв; до неё 0.10.13, `versionCode = 56`: «Как продвигается?» каждый день без ключа, «Выполнено», потолок ответа проверки 1600; до неё 0.10.12, `versionCode = 55`: вопросы агента — класс заметки, вопросы по пробелам, «Разобрать план», «Как продвигается?», SQLite 17; до неё 0.10.11, `versionCode = 54`: чат по заметке меняет заметку по кнопке «Применить», происхождение чатов `chats.origin`, SQLite 16; до неё 0.10.10, `versionCode = 53`: одна заметка — несколько дат, SQLite 15; до неё 0.10.9, `versionCode = 52`: группировка в колоду, добавление в колоду, галочка «Пустые и дубли — в корзину», «Разобрать колоду», подсказка модели в словаре агента; SQLite не менялась, 14; до неё 0.10.8, `versionCode = 51`: словарь действий агента и журнал с «Отменить», SQLite 14; до неё 0.10.7, `versionCode = 50`: корзина, SQLite 13; до неё 0.10.6, `versionCode = 49`: дерево плана у заметки и чат по заметке, SQLite 12; до неё 0.10.5, `versionCode = 48`: ИИ сам предлагает, за сколько напомнить; сводка видео по ссылке в чате и заметная кнопка; точнее предложения групп и уточняющие вопросы, SQLite 11; до неё 0.10.4, `versionCode = 47`: жест «потянуть вниз» на экране заметок запускает обмен с компьютером; до неё 0.10.3, `versionCode = 46`: синхронизация чатов и стопок с компьютером, SQLite 10; до неё 0.10.2, `versionCode = 45`, только смена номера). Идентификатор приложения — `app.fastnotes`, минимальная версия Android — 8.0 (API 26). Сборка поддерживает ARM64 и x86_64. Версию и параметры сборки сверяй с [Gradle](app/build.gradle.kts).

Android 0.10.12, вопросы агента (этап 5 из `docs/AGENT-PLANNER.md`). SQLite **17**.
1) Класс заметки без отдельного запроса: подсказка проверки (`ManagerAnalysis.PROMPT`, у общей проверки `ReviewAnalysis` тоже) просит в том же JSON поле `"kinds":{"ID":"info|simple|event|complex"}` (`TaskKind.GUIDE`). Во входе модели у каждой записи есть `has_reminder`.
2) Вопросы по пробелам: правила в подсказке по классу — info не спрашивать; simple — не больше одного «когда?» и только если срока нет; event — одно недостающее (время, место, с кем, что взять); complex — не спрашивать (приложение предложит план). Вопрос модель формулирует по записи, `options` 0–4. `AgentAction` ASK теперь всегда карточка `clarify` (и без вариантов). Один открытый вопрос на заметку: `ManagerStore.finish` не добавляет новый, пока не отвечен прежний (`pendingQuestion`).
3) Ответы по заметке: `ManagerStore.answers` / `noteAnswers` — «вопрос → ответ», до 5 последних на заметку, **и после правки заметки** (раньше ответ терялся при изменении записи); идут в каждую проверку и в запрос чата по заметке (`PlanChat.context/payload(..., answers, ...)`, `ChatRunner.planReply`) — хвост этапа 6.
4) Интерфейс вопроса: в колокольчике и на экране «Помощник» карточка «Вопрос помощника» — варианты кнопками, «Свой ответ» (окно ввода, до 300 знаков; главная кнопка, если вариантов нет), «Открыть заметку», «Не нужно»; в открытой заметке над планом — блок «Вопрос помощника» с тем же (`questionSection`); на карточке списка — пометка «Вопрос помощника» (`questionNotes`, читается раз на обновление списка).
5) Большая задача: для заметки класса complex без плана `finishReview` добавляет предложение `plan` (identity `plan|<id>`, один раз на заметку; устаревшее может повториться). Колокольчик и «Помощник»: «Разобрать план» → «Разобрать» открывает чат по заметке и просит агента начать разбор (`openPlanChat`), «Не нужно» — больше не предлагать.
6) «Как продвигается?» (бывший `CheckIn`): `CheckInJob.compose` сначала проверяет лимит — не больше 4 чатов, начатых помощником, за сутки (`ProgressCheck.MAX_PER_DAY`, `Store.agentChatsSince`), — затем ищет дело (`CheckInJob.progressCandidate` → чистая Java `ProgressCheck.pick`): разовое напоминание в пределах 2 суток от «сейчас» (ближайшие первыми) или дело (класс simple/event/complex или открытый план) без правок неделю и не старше 2 месяцев; сведения, серии, заметки в колодах (кроме верхней) и те, о которых недавно спрашивали (`progressNext.<id>` в настройках), пропускаются. Нашлось — чат без запроса к модели (`Store.newProgressChat`: `origin=agent`, привязан к заметке, черновик `{"kind":"progress"}`, варианты «Сделано / В процессе / Отложить / Не актуально» строкой `[[ask:…]]`), иначе прежний вопрос, составленный моделью. Уведомление и «Недавно спрашивал» — без служебной строки.

Ответ своими словами уходит агенту чата по заметке (чат привязан к заметке). `Store.noteChat` не берёт чаты помощника: «Обсудить» открывает свой чат заметки.

- На главном экране новая заметка создаётся кнопкой «Сохранить заметку». При пустом названии заголовок берётся из первой строки. Существующая заметка открывается отдельным экраном и сохраняется при выходе. Стрелка назад находится сверху, удаление — в меню «⋮». Служебные даты и метаданные скрыты на экране редактирования.
- Создание заметки сопровождается коротким подтверждением с галочкой. В ИИ-чате источники открываются по ссылкам и карточкам. Предложение создать заметку можно просмотреть и отредактировать перед сохранением. Прямая просьба создать заметку сохраняет корректный результат модели и возвращает ссылку.

## Где менять поведение

- В пакете `app.fastnotes` класс `MainActivity` отвечает за экраны, жесты и формы. `Store` ведёт SQLite, миграции и индекс FTS4. `Metadata`, `SearchQuery` и `Retrieval` формируют метаданные, поисковые запросы и выборку источников.
- `ManagerAnalysis` задаёт контракт предложений; `ManagerStore` хранит очередь, предложения и плоские группы; `ManagerJob` выполняет обзор в общем дневном бюджете. Исходники стопок сохраняются, принятие транзакционное и проверяет версии текстов и состава групп.
- `ChatRunner` и `Polza` готовят контекст и обрабатывают ответы чата. `BackgroundAnalysis` ведёт фоновые проверки. `ImageFiles`, `ImageRunner` и `Vision` отвечают за вложения и анализ изображений. `LocalLlm` подключает llama.cpp через JNI. `Reminders` и приёмники отвечают за расписание и доставку уведомлений.

## Правила данных и ИИ

- Сохраняй пользовательские записи при миграциях SQLite. Синхронизируй индекс при создании, изменении и удалении заметки. Дополнения ИИ применяй к той версии текста, которую получила модель. При правке сбрасывай устаревшие подсказки. Системные даты хранятся отдельно от предположений ИИ.
- Предложение напоминания становится уведомлением после подтверждения пользователем. Время события хранится отдельно от выбранного интервала оповещения. Для платных запросов сохраняй лимиты одного запроса и ручной повтор после ошибки. Дневной предел 4 проверки действует по умолчанию; пользователь может снять его кнопкой и вернуть без сброса счётчика.
- Локальный GGUF обслуживает текстовый чат на устройстве. Переключение на Polza.AI выполняется явно в настройках. Ключ Polza.AI хранится через `Secrets` и Android Keystore.

## Сборка и выпуск

После каждой завершённой правки выполни подходящие проверки и сделай локальный Git-коммит с кратким описанием изменения. Перед коммитом просмотри `git diff --cached` и добавляй только файлы текущей задачи. Пользователь подключил GitHub-репозиторий https://github.com/Ux1ew1/Mimohodom для сборки через Actions. Workflow `.github/workflows/android.yml` запускается на push в main, pull request и вручную. Не отправляй локальные инструменты, ключи и APK. Для совместимой подписи используется Actions secret `DEBUG_KEYSTORE_BASE64`; без него CI APK подписан временным ключом. Фактический результат каждого облачного запуска фиксируй отдельно от локальных проверок.

Храни в Git исходники, тесты и документацию. APK из `dist/`, локальные инструменты, ключи подписи и настройки машины исключены из репозитория. `native/llama.cpp` подключён как подмодуль с закреплённой версией. После клонирования выполни `git submodule update --init --recursive`.

С локальными инструментами на Windows используй `scripts/build-local.ps1`. Для сборки из исходников нужны JDK 17, Android SDK 35, NDK `28.2.13676358` и CMake `3.22.1`.

```powershell
.\scripts\build-local.ps1 -Tasks @('assembleDebug', 'lintDebug')
.\scripts\test-core.ps1
.\scripts\test-polza.ps1
node tests/metadata-sql.cjs
.\scripts\test-manager.ps1
node tests/manager-sql.cjs
.\gradlew.bat assembleDebug assembleDebugAndroidTest lintDebug
# На подключённом устройстве или эмуляторе
.\gradlew.bat connectedDebugAndroidTest
```

Готовый файл выпуска называй `dist/mimohodom-<версия>-debug.apk`. Текущая сборка — [0.9.3](dist/mimohodom-0.9.3-debug.apk). Для установки поверх предыдущей версии увеличивай `versionCode`, сохраняй `applicationId` и используй тот же ключ подписи. Перед выдачей APK сверяй версию и проверяй подпись.

После релиза обнови версию и краткий статус в этом файле, описание нового поведения в README и фактические результаты в `VERIFICATION.md`. Различай успешную сборку тестового APK и запуск тестов на устройстве. Для 0.5.4 остаётся проверить стопки, жесты и предложения менеджера на устройстве, а также миграцию на телефоне и дополнение метаданных с реальной моделью. Генерация с настоящим GGUF на телефоне также ждёт проверки.
