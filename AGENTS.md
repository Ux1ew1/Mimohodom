# Мимоходом

Нативное Android-приложение на Java с локальным хранением. Текущая версия — **0.10.3** (`versionCode = 46`: синхронизация чатов и стопок с компьютером, SQLite 10; до неё 0.10.2, `versionCode = 45`, только смена номера). Идентификатор приложения — `app.fastnotes`, минимальная версия Android — 8.0 (API 26). Сборка поддерживает ARM64 и x86_64. Версию и параметры сборки сверяй с [Gradle](app/build.gradle.kts).

Синхронизация чатов и стопок (Android 0.10.3, desktop 0.10.3.5, протокол — `docs/SYNC.md`, «Чаты и стопки»): Android — `Store.addChatSync` (SQLite 10: `uid, sync_ts, sync_seq, sync_from` у `chats` и `messages`, пять триггеров, таблица `stack_sync`), `SyncRecord` (виды `chat`, `message`, `stack`, `SyncRecord.mapLinks`), `SqliteSyncStore` (`collectChats`, `stampStacks`, `applyChats`); компьютер — `desktop/core/src/sync/chats.rs`, схема v4, `CHAT_TRIGGERS` в `store.rs`. Новые сообщения и чаты нумеруют триггеры, поэтому любой путь записи (чат, `CheckInJob`, помощник) учитывается без правок кода; стопки (`note_groups`, `note_members`) триггеров не имеют и находятся сравнением с `stack_sync` при отправке и приёме. На проводе вместо номеров заметок `uid` (`[[note:<uid>]]`, источники `{"uid","title"}`), при приёме снова номера; неизвестная заметка даёт `[[note:0]]`. Сообщения читаются по `created, id`: любой новый запрос сообщений должен сортироваться так же, не по `id`. Любая новая ссылка на картинку чата должна попадать в `Store.chatImageNames` (её читает и обмен). Сервер отдаёт чаты только клиенту с `features: ["chats"]`. `Store.onCreate` по-прежнему содержит ровно 8 встроенных `execSQL` (`addChatSync` вызывается отдельно и разбирается `tests/sync-sql.cjs`). Проверено на машине агента (SQL на настоящем SQLite, сквозной тест Java ↔ Rust); на телефоне не проверено.

Горячие клавиши компьютера (desktop 0.10.2.4, только `desktop/ui`): один обработчик `document` `keydown` → `onHotkey` в `desktop/ui/app.js`. Esc (`onEscape`) закрывает самое верхнее: открытое окно `modal` (его `close` хранится в `S.modalClose`; не добавляй к своим окнам отдельную обработку Esc, иначе Esc закроет и заметку под ним), затем очищает поиск, затем `leaveEditor()` + `closeEditor()` (как кнопка «Закрыть»). Ctrl/Cmd+S/N/F/K и Ctrl+1…4 (клики по `.nav`); при открытом окне они не работают. Новая клавиша — добавь в `HOTKEYS` (список показывается в настройках) и в документы.

Видео YouTube на компьютере (desktop 0.10.2.3, Android не менялся; схема базы компьютера по-прежнему v3, новых таблиц нет): порт `YoutubeLink`, `VideoAnalysis`, `VideoMerge` и `VideoRunner`; промпты дословно с Android (при правке на телефоне правь и здесь). `core/src/ai/video.rs` — чистая логика: `link_id`/`all`/`only_links`/`canonical` (без внешнего разбора адресов: схема http/https, адрес из списка `HOSTS`, `youtu.be`/`watch?v=`/`shorts|live|embed|v`), `payload`/`parse` (ЗАГОЛОВОК/КРАТКО/ГЛАВНОЕ/ТЕМЫ), `split`/`compose`/`best`/`merge_payload`/`merge_parse` (порог `THRESHOLD`=0,3 по `review::similarity`, `MAX_SECTIONS`=12). `core/src/ai/video_run.rs` — потоки: `start` (по запросу на ролик, `TIMEOUT_SECS`=240, до `MAX_LINKS`=10, повторная ссылка — `note_id_containing`, ошибка прерывает очередь и не повторяется), `merge`, `candidate`, `poll` (результат отдаётся один раз и очищается); состояние `App::video` (`VideoState`), не держи его вместе с блокировкой базы. `Store` (`ai/store.rs`): `save_video` (заметка + подсказки + `mark_reviewed`: `ai_checked` и строка `manager_review`, чтобы помощник не платил за разбор), `video_notes` (без стопок), `merge_video` (проверка версий обеих заметок; без внешней транзакции, потому что `save_note` открывает свою), `note_id_containing`. Команды `api.rs`: `video_info`, `video_start`, `video_poll`, `video_merge_candidate`, `video_merge`; в `ai_state` добавлены `videoModel`, `defaultVideoModel`; модель — настройка `ai.videoModel`. Интерфейс: `offerVideo`, `startVideo`, `watchVideo` (опрос раз в 1,5 с), `videoFinished`, `askNextMerge` в `desktop/ui/app.js`, вход — `saveDraft` (только не при автосохранении) и кнопка «Сводка видео» в редакторе, строка хода `#video-pill`. Тесты: `core/tests/video.rs`, модульные в `ai/video.rs` и `ai/store.rs`; заглушка `tests/fake-polza.cjs` отвечает на `video_url` и «Ниже сводки нескольких видео». Нумерация компьютерной версии (по просьбе пользователя, 18.11): `<версия Android>.<N>`, где N — номер выпуска для компьютера; 0.10.2.3 = Android 0.10.2 и третий выпуск компьютера. Прежние 0.10.0 (этап 1), 0.11.0 (чат), 0.12.0 (помощник) соответствуют .0, .1, .2. В `Cargo.toml`, `tauri.conf.json` и `package.json` версия записывается как `0.10.2-3` (semver не допускает четыре числа; число после дефиса — N, установщик MSI принимает числовой суффикс), в интерфейсе и документах — `0.10.2.3`. Когда выйдет новая версия Android, меняются первые три числа, а N продолжает счёт (допущение, пользователь его не уточнял).

Фоновый помощник на компьютере (desktop 0.12.0, Android не менялся; схема базы компьютера **v3**): порт логики телефона в `desktop/core/src/ai/`, промпты дословно с Android (при правке на телефоне правь и здесь). `review.rs` — чистая логика: `DAILY_LIMIT`=4, `BATCH`=8, `fingerprint` (sha256 полей заметки), общий запрос менеджера и анализа `review_payload`, `manager_parse`/`analysis_parse`/`review_parse`, выбор по темам (`similarity` ≥ 0,18), `summary_payload`/`summary_parse`; `folders.rs` — автопапки; `checkin.rs` — вопросы о планах (`MAX_MISSED`=3, «занят» 20 мин, «устарел» 4 ч); `store.rs` (`impl Store`) — очередь проверки (`manager_review`), предложения (`manager_proposals`), стопки (`note_groups`, `note_members`, на телефон не уходят), журнал (`review_log`, 30 записей), столбцы `notes.suggestion/suggestion_reason/ai_failed`, `chats.kind` (1 = чат помощника); `assistant.rs` — фоновые задачи и `tick` раз в минуту (поток в `api.rs`). Правила: платный запрос после ошибки сам не повторяется (`retry_failed` сбрасывает пометки); `apply_metadata`/`apply_analysis` не меняют `updated`, а смена названия ставит метку синхронизации; сохранение заметки сбрасывает `suggestion`; порядок блокировок: `app.assist` можно держать при взятии `app.store`, наоборот нельзя, при сетевых запросах блокировок нет; в чате помощника ответ пользователя автоматически сохраняется черновиком-итогом; `[[memo]]` остаётся в тексте сообщения. Тесты: `core/tests/assist.rs`, заглушка `tests/fake-polza.cjs` умеет проверку, выжимку и вопрос. Интерфейс: вкладка «Помощник» (`renderAssist` в `desktop/ui/app.js`), метки в списке и плашка в редакторе; опрос значка — `pollSync`.

ИИ-чат на компьютере (desktop 0.11.0, Android не менялся): `desktop/core/src/ai/` — `text.rs` (чистые порты `Retrieval`, ИИ-часть `Metadata`, `ChatImages`, `ReminderBatch`, разбор `[[draft]]`/`[[index]]`/`[[note:ID]]`; тексты для модели дословно с телефона — при правке промпта на Android правь и здесь), `chat.rs` (`prepare`/`finish` = `Polza.ask` в облачном режиме, `vision_*` = `Vision`, `send`/`run` = `ChatRunner`: один запрос за раз, база блокируется только на чтение и запись, не на время сети), `polza.rs` (HTTP, тексты ошибок как на телефоне, адрес `App::ai_base` подменяется в тестах), `keys.rs` (ключ в системном хранилище через `keyring`; `App::open_dev` и тесты держат ключ в памяти). Схема базы компьютера v2: `chats`, `messages` (`draft` — черновик или `{"kind":"reminders"}`), `cache`; чаты не синхронизируются. `Store::apply_metadata` не меняет `updated` и метки синхронизации (как на телефоне). Уборка картинок учитывает картинки чатов и не трогает файлы моложе 6 часов. Настройки: `ai.model`, `ai.imageModel`, `ai.maxTokens` в таблице `settings`. Ручная проверка без оплаты: `node tests/fake-polza.cjs 5199` и `MIMO_AI_BASE=http://127.0.0.1:5199/api` для примера `dev`.

Синхронизация с компьютером (0.10.0, SQLite 9): протокол и правила слияния описаны в `docs/SYNC.md` — читай его, прежде чем менять обмен; Rust-ядро (`desktop/core`) и Java-клиент реализуют их независимо и проверяются друг против друга (`tests/sync-e2e.cjs`). Java: `SyncCrypto` (HKDF-SHA256 + AES-256-GCM), `SyncRecord`, `SyncPairing` (строка `mimohodom://pair?...`), `SyncStore` (интерфейс хранилища) и `SqliteSyncStore` (реализация поверх `Store`; `apply`/`applyNote` зеркалят `engine.rs`), `MiniHttp` (клиент на сокетах: обычный HTTP по локальной сети запрещён политикой cleartext), `SyncClient` (обмен: страницы, картинки, коды ошибок), `PeerSync` (запуск в одном фоновом потоке, не чаще раза в 90 с, из `onResume`/`onPause`; после принятых заметок переставляет напоминания и запускает `CalendarSync`). Экран — настройки → «Синхронизация» (`settingsSync`), сканер QR — `GmsBarcodeScanning` (системный, без разрешения CAMERA; при недоступности — ввод строки). В `Store` версии 9 (`addSync`): столбцы `uid, sync_ts, sync_seq, sync_from` у заметок и папок, `sync_meta`, `sync_peers`, `tombstones`; триггеры на правку (только содержательные столбцы: название, текст, created, updated, напоминание, повтор, «за N», картинки, папка — чтобы фоновая ИИ не перебивала чужую правку) и удаление. Триггера на вставку заметки **нет** (вложенный UPDATE дублирует строку в FTS): новые заметки нумерует `SqliteSyncStore.stampPending` при первом обмене. `Store.onCreate` по-прежнему содержит ровно 8 inline-вызовов `execSQL` (на них опираются node-тесты), синхронизация вынесена в `addSync`. Папки сопоставляются по `uid` = первые 32 hex SHA-256(`"folder:"` + ключ), поэтому одноимённые папки на двух устройствах сходятся. Компьютерная версия — `desktop/` (Tauri 2): `core` (Rust: `store`, `policy`, `sync/*`, `api::dispatch`), `src-tauri` (оболочка, одна команда `rpc`), `ui` (HTML/JS/CSS без сборщика).

Тёмная тема (0.9.7): настройка `theme` (`auto` по умолчанию = системная, `light`, `dark`) читается в `onCreate` до `super` (`wantsDark` → `applyPalette` + `setTheme(AppThemeLight|AppThemeDark)`); цвета в `MainActivity` — не `final` статические поля (`PAPER, INK, MUTED, GREEN` текст/значки акцента, `FILL` заливка главных кнопок с белым, `SURFACE` карточки/поля, `WHITE` — только текст на цветной заливке, `DOCK, STROKE, STACK_*, REMINDER_BG, RECAP_BG`). Новые цвета добавляй в обе ветки `applyPalette`, не вводи литералы. Смена настройки или системной темы пересоздаёт активность. Темы окна — `res/values*/styles.xml`.

Пачка напоминаний (0.10.1): у заметки по-прежнему одно напоминание (схема SQLite не менялась), несколько дат — это несколько заметок. ИИ в конце ответа добавляет блок `[[reminders]]` со строками `2026-11-06 16:00 | Название | пояснение` (подсказка `ReminderBatch.guidance()` в системном промпте облачной модели; локальным моделям не даётся). `Polza.ask` разбирает его `ReminderBatch.parse` (чистая Java: только будущие даты, без повторов, до 40 строк, название ≤ 80) и кладёт в `Answer.reminders`; `ChatRunner` пишет предложение в столбец `messages.draft` как `{"kind":"reminders","items":[…]}` (рядом с черновиком заметки, показ — `MainActivity.reminderBatchView`, определение — `ReminderBatch.isBatch`). Для запросов со словом «напом…» лимит ответа не меньше 3000 токенов (`ReminderBatch.wants`), чтобы блок не оборвался. `Store.acceptReminders(message, skip)` в одной транзакции создаёт заметки (`save(0, title, body, at)`, тело = пояснение или название), добавляет их в `sources` сообщения и дописывает «Создано напоминаний: N»; будильники ставит `MainActivity` (`Reminders.schedule`, затем один `CalendarSync.runAsync`). Редактор: если в тексте ≥ 2 дат (`ReminderBatch.manyDates`), в меню напоминания есть «Напоминания по всем датам в тексте» (`remindersFromText`: кладёт `ReminderBatch.requestFor` в черновик нового чата и открывает его, отправляет пользователь). Тесты: `scripts/test-reminder-batch.ps1`.

Точность картинок (0.9.6): `ChatImages.MIN_ANSWER_TOKENS` = 6000 (`answerTokens`) — нижняя граница лимита ответа в запросе с картинками (при 600 ответ обрывался, а Gemini 2.5 Pro тратил весь лимит на рассуждения и возвращал пустой ответ); `ChatImages.questionHint()` добавляется в конец последнего сообщения после вопроса через `Polza.ask(..., images, tail)` (не попадает в поиск по заметкам и в сохранённое сообщение): модель сначала выписывает все строки таблицы с отметкой признака, потом итог; `ChatImages.guidance` дополнен правилами для таблиц. Проверка: два фото расписания с зелёным маркером, `google/gemini-2.5-flash` без памятки пропускал строку 12.11, с памяткой нашёл все 11 выделенных строк (лишней осталась зачёркнутая 19.11); `google/gemini-2.5-pro` строки тоже пропускал. Мост не даёт менять настройки с «token» в имени.

Исправления 0.9.5 (отчёт `app-tester` по картинкам): `imageStrip` помнит `stripScroll` и возвращает ленту на место после `render()`, выбранная плитка остаётся видимой; «Новый чат» и действие `NEW_CHAT` не трогают `chatImage.0` (черновик нового чата хранится вместе с текстом `chatDraft.0`); удаление чата освобождает и `chatImage.<id>`; «×» вложения 36 dp (видимый кружок 22 dp через `InsetDrawable`), «Действия» от 44 dp, описания плиток с номером.

Картинки в чате (версия 0.9.4). Чат больше не «одна картинка → заметка»: имена файлов лежат в тексте сообщения пользователя блоком `[[img:a.jpg,b.jpg]]` (как `[[memo]]`; схема SQLite не менялась, остаётся 8). Чистая Java `ChatImages` (тест `scripts/test-chat-images.ps1`): `attach`, `split`, `all` (картинки чата по порядку, номер №k стабилен), `select` (самые новые не больше `MAX_IN_REQUEST` = 6 штук и `MAX_REQUEST_BYTES` = 6 МБ), `forModel` (в тексте для модели блок заменяется на «[Приложено: изображение №2]»), `guidance`. `ChatRunner.send(..., image, imageModel)`: `image` — вложения этого сообщения (`chatImage.<chat>`, список через запятую, до `MAX_ATTACH` = 6); сообщение пишется с блоком, после чего вложение в настройках снимается — картинки принадлежат чату. Если у сообщения есть картинки и текст пуст (`ChatRunner.NOTE_QUERY`) или `Polza.wantsNote(query)`, идёт прежний путь «заметка по картинкам» (`Vision`, `Store.saveVision` со списком); иначе обычный ответ `Polza.ask(..., guidance, images)`: части «подпись + image_url» кладутся в последнее сообщение пользователя перед вопросом, таймаут ответа 180 с, модель — `imageModel` (настройка «Модель для картинок», по умолчанию `Vision.DEFAULT_MODEL` = `google/gemini-2.5-flash`). Запрос с картинками идёт этой моделью весь остаток чата. Повтор после ошибки узнаёт своё сообщение (`ChatImages.split(...).text`) и не дублирует его. Картинки чатов входят в `ImageFiles.referenced` через `Store.chatImageNames` (поиск `instr(body,'[[img:')`); при удалении чата их файлы освобождаются `ImageFiles.release`. Локальный режим: картинки не отправляются, прикрепить новую нельзя. Выбор картинок: `pickImage` → «Галерея» (`MediaStore.ACTION_PICK_IMAGES` на API 33+, код 91, `EXTRA_PICK_IMAGES_MAX`), «Файлы» (`ACTION_OPEN_DOCUMENT` + `EXTRA_ALLOW_MULTIPLE`, код 88) или камера (код 90); `attachImages` импортирует по одной в потоке `io` и сообщает, сколько добавлено/не поместилось. `ImageFiles.importImage` сжимает до 2048 px (качество 88→78→68, файл до 2 МБ). Заметка: `imageStrip` (миниатюры 72 dp, повторное нажатие на выбранную открывает просмотр) и кнопка «Действия» (`showImageActions`) вместо крупного превью и столбца кнопок. На устройстве не проверено.

Вопросы о планах (версия 0.9.1): помощник сам пишет первым. `CheckIn` — правила без Android (расписание `nextAt`, промпт, `clean`, `followUp`; тест `scripts/test-checkin.ps1`), `CheckInJob` — будильник → `ReminderReceiver` (действие `CHECKIN`) → задача с сетью → один запрос → новый чат (`Store.newAssistantChat`) и уведомление `checkin`. Чат помечен настройкой `checkInChat.<id>`; для такого чата `ChatRunner` передаёт `CheckIn.followUp` в `Polza.ask(..., guidance)`, и помощник продолжает расспрашивать по ситуации. Вопросов нет в виде готового списка: их пишет модель. Один платный запрос, без автоповторов; три вопроса подряд без ответа — пауза; при GGUF на паузе (`LocalLlm.cloudBackground`). Будильник ставится `CheckInJob.arm` (запуск приложения, перезагрузка, смена настроек). По умолчанию спрашивает раз в день (`CheckIn.DEFAULT_EVERY = 1`). Память чата: `ChatMemo` (без Android, тест в `scripts/test-checkin.ps1`) — модель в конце ответа пишет `[[memo]]факт на строке[[/memo]]`, `Polza.ask` кладёт факты в `Answer.facts`, `ChatRunner` прикрепляет их к тексту сообщения (`ChatMemo.attach`), интерфейс показывает серым «✓ Запомнил». В чатах помощника блок `draft` не ждёт подтверждения: `ChatRunner` сам записывает заметку (или обновляет прежнюю, `checkInNote.<chat>` = `id:updated`, пока пользователь её не правил; правленую не трогает, оставляя предложение) и добавляет сообщение-итог `ChatMemo.recap` (метка `[[recap]]`). Напоминание не ставится. Это исключение из правила подтверждения черновиков действует только для чатов с признаком `checkInChat.<id>`. ИИ-чат сделан компактным: `compactButton`, `chatNote`, шрифт сообщений 14 sp. На устройстве не проверено.

## Интерфейс

- Основная палитра — светлый фон `#F7F8F2` и зелёный акцент `#28634B`. Нижняя панель плавающая, по центру внизу, без подписей; значки идут в порядке «Заметки», «Записать», «ИИ-чат» (индексы вкладок 0, 1, 2; стартовая — «Записать»). Настройки — вне панели (индекс 3), кнопка в правом верхнем углу рядом с колокольчиком предложений ИИ. На экране «Заметки» сверху стрелка назад, поле поиска и кнопки; поле раскрывается с быстрым стартом и замедлением. Углы скруглены на 10–14 dp. Горизонтальные свайпы плавно перелистывают три вкладки, нижняя панель остаётся на месте.
- На главном экране новая заметка создаётся кнопкой «Сохранить заметку». При пустом названии заголовок берётся из первой строки. Существующая заметка открывается отдельным экраном и сохраняется при выходе. Стрелка назад находится сверху, удаление — в меню «⋮». Служебные даты и метаданные скрыты на экране редактирования.
- Создание заметки сопровождается коротким подтверждением с галочкой. В ИИ-чате источники открываются по ссылкам и карточкам. Предложение создать заметку можно просмотреть и отредактировать перед сохранением. Прямая просьба создать заметку сохраняет корректный результат модели и возвращает ссылку.

## Где менять поведение

- В пакете `app.fastnotes` класс `MainActivity` отвечает за экраны, жесты и формы. `Store` ведёт SQLite, миграции и индекс FTS4. `Metadata`, `SearchQuery` и `Retrieval` формируют метаданные, поисковые запросы и выборку источников.
- `ManagerAnalysis` задаёт контракт предложений; `ManagerStore` хранит очередь, предложения и плоские группы; `ManagerJob` выполняет обзор в общем дневном бюджете. Исходники стопок сохраняются, принятие транзакционное и проверяет версии текстов и состава групп.
- `ChatRunner` и `Polza` готовят контекст и обрабатывают ответы чата. `BackgroundAnalysis` ведёт фоновые проверки. `ImageFiles`, `ImageRunner` и `Vision` отвечают за вложения и анализ изображений. `LocalLlm` подключает llama.cpp через JNI. `Reminders` и приёмники отвечают за расписание и доставку уведомлений.

## Правила данных и ИИ

- Сохраняй пользовательские записи при миграциях SQLite. Синхронизируй индекс при создании, изменении и удалении заметки. Дополнения ИИ применяй к той версии текста, которую получила модель. При правке сбрасывай устаревшие подсказки. Системные даты хранятся отдельно от предположений ИИ.
- Предложение напоминания становится уведомлением после подтверждения пользователем. Время события хранится отдельно от выбранного интервала оповещения. Для платных запросов сохраняй лимиты одного запроса и ручной повтор после ошибки. Дневной предел 4 проверки действует по умолчанию; пользователь может снять его кнопкой и вернуть без сброса счётчика.
- Локальный GGUF обслуживает текстовый чат на устройстве. Переключение на Polza.AI выполняется явно в настройках. Ключ Polza.AI хранится через `Secrets` и Android Keystore.

## Сборка и выпуск

После каждой завершённой правки выполни подходящие проверки и сделай локальный Git-коммит с кратким описанием изменения. Перед коммитом просмотри `git diff --cached` и добавляй только файлы текущей задачи. Пользователь подключил GitHub-репозиторий https://github.com/Ux1ew1/Mimohodom для сборки через Actions. Workflow `.github/workflows/android.yml` запускается на push в main, pull request и вручную. Не отправляй локальные инструменты, ключи и APK. Для совместимой подписи используется Actions secret `DEBUG_KEYSTORE_BASE64`; без него CI APK подписан временным ключом. Фактический результат каждого облачного запуска фиксируй отдельно от локальных проверок.

Храни в Git исходники, тесты и документацию. APK из `dist/`, локальные инструменты, ключи подписи и настройки машины исключены из репозитория. `native/llama.cpp` подключён как подмодуль с закреплённой версией. После клонирования выполни `git submodule update --init --recursive`.

С локальными инструментами на Windows используй `scripts/build-local.ps1`. Для сборки из исходников нужны JDK 17, Android SDK 35, NDK `28.2.13676358` и CMake `3.22.1`.

```powershell
.\scripts\build-local.ps1 -Tasks @('assembleDebug', 'lintDebug')
.\scripts\test-core.ps1
.\scripts\test-polza.ps1
node tests/metadata-sql.cjs
.\scripts\test-manager.ps1
node tests/manager-sql.cjs
.\gradlew.bat assembleDebug assembleDebugAndroidTest lintDebug
# На подключённом устройстве или эмуляторе
.\gradlew.bat connectedDebugAndroidTest
```

Готовый файл выпуска называй `dist/mimohodom-<версия>-debug.apk`. Текущая сборка — [0.9.3](dist/mimohodom-0.9.3-debug.apk). Для установки поверх предыдущей версии увеличивай `versionCode`, сохраняй `applicationId` и используй тот же ключ подписи. Перед выдачей APK сверяй версию и проверяй подпись.

После релиза обнови версию и краткий статус в этом файле, описание нового поведения в README и фактические результаты в `VERIFICATION.md`. Различай успешную сборку тестового APK и запуск тестов на устройстве. Для 0.5.4 остаётся проверить стопки, жесты и предложения менеджера на устройстве, а также миграцию на телефоне и дополнение метаданных с реальной моделью.
